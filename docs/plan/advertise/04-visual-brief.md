# Visual brief

## 1. System

The preserved poster keeps its original visual identity. The two explanatory figures deliberately do not inherit that palette: they use a pure white field, graphite technical linework, neutral gray, and one restrained deep-blue accent. Their visual language follows publication-quality computer-systems figures rather than brand graphics or presentation slides. It avoids card UI, drop shadows, decorative scenes, people, faces, and product logos.

## 3. Intent to autonomy abstract

- Path: `docs/assets/figures/intent-to-autonomy.png`
- Dimensions: 1536 × 1024
- Inputs: Project facts; User intent; Non-negotiable constraints
- Stages: Audit; Interview; Route; Generate; Validate
- Output: Project-specific Claude Code harness
- Outcomes: Judgment preserved; Boundaries enforced

All arrows move from inputs through the ordered stages to the output and two outcomes.

The composition uses converging evidence traces, a continuous transformation rail, and a layered system cutaway instead of a sequence of presentation boxes.

## 4. Principles and verified boundaries abstract

- Path: `docs/assets/figures/principles-and-verified-boundaries.png`
- Dimensions: 1536 × 1024
- Judgment lane: Principles + context → Model judgment → Adapt to the case
- Enforcement lane: Non-negotiable constraints → Hooks · permissions · tests → Block or verify
- Convergence: Adaptable behavior within verified boundaries

Adaptive judgment is encoded as a branching inference field. Deterministic enforcement is encoded as a measured verification rail. Their arrowed convergence makes the relationship legible without relying on color alone.

## 5. Linked source video

GitHub README rendering does not support an interactive YouTube iframe. The README therefore uses the supplied YouTube thumbnail as a large linked image that opens Boris Cherny's discussion at 12:20. This remains supporting engineering rationale inside the philosophy section rather than the product's lead pitch.

## 6. Accessibility

Every figure receives descriptive alt text and a prose caption. The documentation never depends on the image alone to communicate the relationship. The architecture page uses Mermaid for the exact technical flow because code-native diagrams are easier to verify and maintain than raster text.
